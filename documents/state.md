## State consolidation summary

- Added a shared state package at `packages/state` with Jotai atoms, shared hooks, and a `StateProvider` to centralize data/query logic between web and native.
- Implemented a storage adapter layer with `createPersistedAtom` and platform adapters (web localStorage, native SecureStore) so persisted atoms stay in sync.
- Wired both apps to the shared state package: web `Providers` now wraps `StateProvider`, native root layout now wraps it too.
- Session ownership is now centralized in the shared state layer. Web dashboard and native root layout both gate off the shared session query instead of issuing separate first-load `getSession()` reads.
- While the web dashboard waits for the session check, `DashboardQueries` (`apps/web/src/components/dashboard-queries.tsx`) subscribes to its first queries (tasks, tags, linked accounts, calendars, events, WHOOP), so they run alongside the check; nothing is stored on the device. A signed-out visitor's requests fail as oRPC `UNAUTHORIZED` or a Better Auth 401 (the apps call `listAccounts` with `throw: true`, so it throws an error with `status`). The web query client neither retries nor toasts these, and the layout redirects to `/login`. The same errors with a session loaded mean the session ended, so the query client refetches it and the layout redirects.
- Migrated web and native imports to use shared atoms/hooks; removed legacy web atoms/hooks and added web-only replacements at `apps/web/src/state/sidebar.ts` and `apps/web/src/lib/use-mobile.ts`.
- The dashboard and native calendar now rely directly on the normal granular TanStack Query hooks instead of a separate bootstrap prefetch path.
- Updated dependencies to include `@kompose/state` and adjusted TypeScript config/types for the new package; verified `@kompose/state` type-check passes.

## `packages/state` contents

- `collision-utils.ts`: Shared layout for overlapping calendar items (web + native). Items that start within 30 minutes of a group's first one sit side by side in it; a later one stacks on top, indented one level, so a long block keeps its width and its title shows. Nothing is covered before 15 minutes of it shows.
- `atoms/command-bar.ts`: Command bar open state and focused task id atoms.
- `atoms/auth.ts`: Auth convenience atoms, including synchronous
  `lastUsedLoginMethodAtom` sourced from the configured auth client.
- `atoms/current-date.ts`: Calendar date, timezone, visible days, event window atoms, and reactive `todayPlainDateAtom` / `nowZonedDateTimeAtom` (refreshed every 60s and on window focus/visibility via `todayTickAtom`).
- `atoms/google-colors.ts`: Google color palette atoms with normalization helpers.
- `account-query-keys.ts`: Shared query keys for linked Better Auth account discovery.
- `atoms/google-data.ts`: Shared linked Better Auth account query, Google-account derivations, per-account calendars, and derived visible calendar ids. The effective visible set is calculated during reads: if no explicit preference is saved yet, all currently loaded calendars are treated as visible; explicit saved selections are filtered against known linked accounts/calendars at runtime. When stale account ids are pruned during derivation, a microtask writes the cleaned selection back to persisted storage so every platform converges. `googleCalendarsLoadingAtom` is true until the linked accounts, each Google account's calendars, and the saved calendar choice have loaded once.
- `atoms/visible-calendars.ts`: Visible calendar selection atoms, a persisted-storage hydration flag, and toggle helpers. Missing persisted state remains `null` as "no explicit preference yet".
- `atoms/whoop-data.ts`: WHOOP account derivation from the shared linked-account query, month-anchored day summaries query atom with ±7 day padding and `keepPreviousData`, and derived `whoopSummariesByDayAtom` map. `shouldShowWhoopRow` keeps the day headers' WHOOP row while WHOOP is linked, or while any visible day has stats (`hasWhoopStats`), so the grid doesn't move when paging to days without data. Components read directly via `useAtomValue` — no prop drilling needed.
- `event-creation.ts`: Why a new event can't be made yet (`eventCreationBlockedReason`: calendars loading, no Google account, or no visible calendar you can edit), in the same words on web and iOS.
- `event-recurrence-words.ts`: A series repeat in words and the monthly day choices. Unsupported rule parts are marked custom. Optional end labels show UNTIL dates or counts.
- `config.ts`: Shared config atom plus helpers for accessing `orpc` and auth client.
- `held-save.ts`: Options and failure messages for a save an editor holds open for, and how a failed one is reported.
- `hooks/use-google-accounts.ts`: Query hook for Google-linked Better Auth `Account` records derived from the shared linked-account query.
- `hooks/use-google-event-mutations.ts`: Create/update/delete Google event mutations with optimistic updates. An editor or dialog that stays open while saving passes `HeldSave` (`quiet`, `failureMessage`, reported through `reportHeldSaveFailure`; the create's, update's and delete's options are `createGoogleEventMutationOptions`, `updateGoogleEventMutationOptions` and `deleteGoogleEventMutationOptions`) and, for an update, `optimistic: false`, so the event isn't moved under it mid-save. Only a one-off create, an unheld update of one occurrence and a delete change the cache before the server answers, and a failure takes back only that change (the stand-in; each list's old copy, where the edit still shows; the removed event, to the lists it left), so what a refetch brought meanwhile stays. After every write the calendar's series masters are invalidated too (`invalidateGoogleEventQueries` in `google-calendar-query-keys.ts`), so the next save never reads a stale rule.
- `hooks/use-google-events.ts`: Query hook for events, one query per calendar and month window (`eventWindowsAtom`: each month the visible days ±7 touch, so the page after the visible one is already loaded). Events crossing a month boundary come back in both months and are deduped by ID.
- `hooks/use-google-account-profiles.ts`: Shared profile hook for linked Google accounts using Better Auth `OAuth2UserInfo`. It can fetch eagerly, but only surfaces that actually render linked-account metadata should depend on it for display.
- `hooks/use-move-google-event-mutation.ts`: Google event move mutation (`moveGoogleEventMutationOptions`). It changes nothing in the cache before the server answers, then refetches both calendars' events and series. An editor holding the save passes `HeldSave` (`quiet`, `failureMessage`), reported through `reportHeldSaveFailure` as for updates.
- `hooks/use-recurring-event-master.ts`: Recurring master query hook. Its failure shows beside Repeat (`meta.quietError`, typed in `state-provider.tsx`), not as a toast.
- `hooks/use-realtime-sync.ts`: Shared SSE sync hook. Initial connects now stay quiet; broad task/calendar invalidation only happens after an explicit `reconnect` event.
- `hooks/use-tasks.ts`: Shared task query + optimistic mutations. An editor that holds open until its save ends passes `optimistic: false`: nothing changes early, and the saved rows are merged into the cache (`task-cache.ts`) as soon as the server answers.
- `hooks/use-today-tick.ts`: Keeps `todayPlainDateAtom` and `nowZonedDateTimeAtom` fresh by incrementing `todayTickAtom` every 60 seconds and on window focus/visibility change. Mounted in `StateProvider`.
- `hooks/use-task-sections.ts`: Shared task sections (Inbox + Today with Overdue/Unplanned/Done) using reactive today/now atoms for correct overdue detection across midnight boundaries.
- `google-event-editability.ts`: Calendar access-role checks for the UI, combined with Google event editability. Readers get read-only event details and cannot be selected as write destinations.
- `google-event-times.ts`: The `EventTime` type and `withEditedTime`, which gives an event's start or end the edited time without the date form it no longer has.
- `google-event-recurrence.ts`: The repeat editor model: parse and build rules, preserve parts the editor cannot show, select days and frequencies, and hydrate the occurrence repeat display. Moving an event does not rewrite its rule.
- `recurrence-scope-options.ts`: The three Google event scopes and shared dialog wording. Saves wait for the series to load. A new repeat disables Only this occurrence; a move to another day disables Entire series because the server keeps the series date. A new calendar disables the other two: Google moves a series to another calendar only as a whole, and an occurrence can't move on its own.
- `series-edit.ts`: Only the details changed in the editor are sent for a series update, so an occurrence’s unchanged title and other details do not spread to the series. Times are sent directly. savedSeriesRecurrence reads the saved repeat for change detection.
- `soft-hyphens.ts`: `withSoftHyphens`, which lets long words in narrow calendar blocks break with a hyphen, three letters kept on each side.
- `state-provider.tsx`: `StateProvider`, which sets the storage adapter, hydrates the config and shared QueryClient atoms, and runs the today-tick refresh. It also declares the typed query meta (`quietError`) both apps' query error handlers read.
- `storage.ts`: Storage adapter interface, persisted atom helper, and web adapter.
- `temporal-utils.ts`: Shared Temporal helpers for date math, and the time and range words web and iOS both show (`formatEventWhen`, `formatAllDayWhen`, `formatTimeRange`, `formatClockTime`/`formatClockRange`, `formatDuration`, `formatScheduledAt`, with a fallback where Hermes lacks `Intl.RelativeTimeFormat`). It also snaps a touch to the nearest slot (`nearestSlotMinutes`), and `moveEventStart` keeps an event's length when its start moves (real time when given the zone, so over a clock change too, and then with its ends as moments, since a clock time alone can't say which half of a repeated hour it's in; a start the clocks skip comes back as the time it lands on; zero stays zero).
- `types.ts`: Shared auth client types.
